## 슬라이드 8: 로직 — 3단계 검증 (1분 30초) ★핵심★

> "확실한 건 코드로, 복잡한 건 AI로. 3단계입니다."

```
L1 형식 검증 (0.1초)  →  하드코딩 21개 룰 (기존 매크로 100% 커버)
L2 교차 검증 (0.5초)  →  진단 답변 vs 명부 자동 비교
L3 AI 검증 (3~5초)    →  정년초과, 패턴 이상, 맥락 추론
```

### L1 — 21개 룰 (기존 매크로 완전 대체)

| # | 룰 |
|---|-----|
| 1-3 | 금액 음수 체크 (당년도/차년도 퇴직금, 중간정산) |
| 4 | 입사연령 17~70세 |
| 5 | 입사일 > 생년월일 |
| 6-8 | 날짜 순서 (중간정산일 > 입사일, 시산일 관계) |
| 9-11 | 날짜 형식 오류 |
| 12 | 기준급여 >= 최저임금 (2,060,740원) |
| 13-17 | 필수값 누락 (사원번호/생년월일/입사일/급여/직종) |
| 18-20 | 임원/계약직 퇴직금 필수 체크 |
| 21 | 재직자 중복 체크 |

### L2 — 교차검증
- 인원수: 사용자 답변 vs 명부 자동 집계 (정확 일치)
- 금액: 사용자 답변 vs 명부 합계 (±5% 허용)

### L3 — AI
- 정년초과 탐지, 임원-급여 이상, 미지의 패턴 추론

**반드시 말할 것:**
> "기존 매크로 21개 에러체크를 L1에서 100% 커버합니다. 거기에 L2 교차검증과 L3 AI를 더했습니다."

# PART 3. 예상 질문 & 답변 (★중요★)

## Q1. "기존 매크로랑 뭐가 달라요?"

> "기존 매크로 21개 에러체크를 L1에서 100% 구현했습니다. 거기에 교차검증(L2)과 AI(L3)를 더한 거예요. 매크로는 형식만 보는데, 우리는 '인원수가 답변과 맞는지', 'AI가 볼 때 이상한 패턴은 없는지'까지 봅니다."

## Q2. "AI 없으면 어떻게 돼요?"

> "Graceful Degradation 설계입니다. OpenAI API 없어도 L1(규칙 21개) + L2(교차검증)는 100% 동작합니다. AI 매칭도 규칙 기반 fallback이 있어서 작동은 합니다."

## Q3. "개인정보 문제는?"

> "설계 단계부터 PII가 필요 없게 만들었습니다. 검증에 필요한 건 사원번호, 생년월일, 입사일, 급여, 퇴직금인데 여기에 주민번호나 이름은 불필요합니다. 만약 포함돼도 PII 자동 탐지 & 마스킹 모듈이 있습니다."

## Q4. "학습이 뭔데요?"

> "사용자가 '이건 오류 아님'을 클릭하면 패턴이 DB에 저장됩니다. 다음에 같은 패턴이 나오면 자동 억제돼요. 세라젬 파일에서 97건 오류 중 93건에 '값 유지' 누르면, 다음엔 4건만 뜹니다."

## Q5. "3단계 검증이 왜 필요해요?"

> "확실한 건 빠르게, 복잡한 건 깊이 있게 보려고요."
> - L1 (0.1초): 날짜 형식, 음수, 필수값 — 확실한 오류를 빠르게
> - L2 (0.5초): 사용자 답변과 명부 비교
> - L3 (3~5초): AI가 전체 맥락 보고 판단
>
> "L1에서 잡힌 건 AI에 안 보내서 비용도 절감됩니다."

## Q6. "컬럼 매핑은 어떻게?"

> "3단계입니다."
> 1. 규칙 기반: "사번" = "사원번호" 같은 alias 매칭
> 2. AI 매칭: 규칙으로 안 되면 GPT-4o에 요청
> 3. 수동 매핑: 그래도 안 되면 드롭다운으로 선택
>
> "규칙으로 되는 건 규칙으로, 안 되는 것만 AI에 보내서 비용 최적화했습니다."

## Q7. "5분이 진짜예요?"

> "시스템 자체는 5~10초입니다. 5분은 사용자가 진단 질문 답변하고 파일 올리는 시간까지 포함한 거예요. 기존 2~3시간 대비 5분입니다."

## Q8. "다른 팀이랑 차이?"

> 4가지:
> 1. **하이브리드**: AI+규칙 둘 다 → 비용 효율 + 정확도
> 2. **매크로 100% 호환**: 업무 전환 비용 0
> 3. **학습**: 쓸수록 정확
> 4. **PII 불필요 설계**: 개인정보 없이 검증 가능

## Q9. "기술 스택?"

| 구분 | 기술 |
|------|------|
| Frontend | React 18 + TypeScript + Vite |
| Backend | FastAPI (Python 3.11) |
| AI | OpenAI GPT-4o |
| DB | SQLite |
| 알림 | Telegram Bot API |
| 보안 | JWT, AES-256-GCM, RBAC |

## Q10. "앞으로 뭘 할 건가요?"

> "명부 검증(완성) → 재정 검증(적립금/부채) → 퇴직급여 자동 산출. 최종 목표는 파일 하나로 원패스입니다."

## Q11. "모드가 2개인데 차이가 뭐예요?"

> - **Basic (roster)**: 명부 형식만 검증. 금액 관련 체크 스킵. 빠르게 확인용.
> - **Complete (full)**: 전체 21개 룰 + 금액 비교 + 최저임금 체크. 정밀 검증용.
> "Basic은 명부 구조만 빠르게 확인할 때, Complete는 제출 전 최종 검증할 때 씁니다."

## Q12. "종업원구분이 뭔가요?"

> "명부에서 사람을 분류하는 코드입니다."
> - 1, 2 = 직원
> - 3 = 임원
> - 4 = 계약직
> "임원/계약직은 당년도+차년도 퇴직금추계액이 필수입니다. 빈칸이면 오류로 잡아요."

# PART 4. 기술 상세 (깊게 물어올 때)

## 4-1. 필수 필드 8개

| 필드 | 타입 | 용도 |
|------|------|------|
| 사원번호 | string | 중복 체크, 고유 식별 |
| 생년월일 | date | 연령/정년 계산 |
| 성별 | category | 1/2 또는 M/F |
| 입사일자 | date | 근속 계산 |
| 기준급여 | number | 최저임금 체크 |
| 당년도퇴직금추계액 | number | 핵심 검증 대상 |
| 종업원구분 | category | 임원/직원/계약직 |
| 근속년수 | number | 퇴직금 산출 기준 |

각 필드는 alias 매핑 지원 (사원번호 ← 사번/직원번호/employee_id)

## 4-2. 직원 인원 계산 방식

```
직원 = 전체 행 수 - 임원(코드3) - 계약직(코드4)
```
종업원구분이 빈칸이거나 비표준 코드여도 직원으로 간주.
→ 사용자 입력값과 명부 집계가 일치하게 됨.

## 4-3. 데이터 흐름 전체

```
[사용자]
  ├─ 진단 질문 답변 (74개)
  ├─ 엑셀 파일 업로드
  │     ↓
  │  [Excel Parser] → 헤더 자동 탐지 (한글 키워드 기반)
  │     ↓
  │  [Header Matcher] → 규칙 매칭 → (안 되면) AI 매칭
  │     ↓
  │  [DataFrame 생성] → 표준 컬럼명 매핑
  │     ↓
  │  ┌─ [L1 형식 검증] → 21개 룰
  │  ├─ [L2 교차 검증] → 답변 vs 집계
  │  └─ [L3 AI 검증]  → GPT-4o
  │     ↓
  │  [중복 제거] → 같은 사원+같은 필드 = 하나로
  │     ↓
  │  [학습 패턴 적용] → false positive 억제
  │     ↓
  │  결과: { errors, warnings, checks, confidence }
  │
  ├─ "값 수정" → SheetEditor → 재검증
  ├─ "값 유지" → 학습 DB 저장
  └─ 다운로드 (검증 리포트 / 최종 명부)
      ↓
  [텔레그램 알림] → 승인/거부
```

## 4-4. 시스템 아키텍처

```
Frontend (React + TypeScript + Vite)
  │ REST API (axios)
  ↓
Backend (FastAPI + Python 3.11)
  ├─ core/validators/   → 3계층 검증
  ├─ core/parsers/      → 엑셀 파싱
  ├─ core/ai/           → AI 매칭, LLM
  ├─ core/privacy/      → PII 탐지/마스킹
  ├─ core/generators/   → 리포트 생성
  ├─ core/database.py   → SQLite (6개 테이블)
  └─ integrations/      → Telegram, n8n
```

**DB 테이블:**
- validation_history, cases, learned_patterns
- error_rules, behavior_events, system_settings

## 4-5. 학습 파이프라인 상세

```
"값 유지" 클릭

→ learned_patterns 테이블에 저장:
   { field, error_message, correct_interpretation, context }
→ 다음 검증 시:
   validator.py가 패턴 로드 → 매칭되면 해당 오류 억제
   → "[학습 패턴 적용됨]" info 경고로 투명 표시
```

## 4-6. Graceful Degradation

| 외부 서비스 | 있을 때 | 없을 때 |
|------------|---------|---------|
| OpenAI API | AI 매핑 + L3 검증 | 규칙 기반 매핑 + L1/L2만 |
| Telegram | 실시간 알림 | 알림 비활성, 검증 정상 |
| Redis | 세션 캐시 | 인메모리 세션 |

→ 핵심 기능(검증)은 외부 API 없이도 100% 동작
