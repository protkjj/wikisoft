# WIKISOFT 4.1 프로젝트 발표자료

> AI 기반 퇴직연금 명부 검증 플랫폼

---

## 1. 프로젝트 개요

### 배경 및 문제점
- 퇴직연금 계리평가 시 **수작업으로 엑셀 명부 검증** → 시간 소요, 휴먼 에러 발생
- 고객사마다 **다른 컬럼명** 사용 (급여/기준급여/월급여 등)
- 검증 기준이 **담당자 경험에 의존**

### 해결 방안
**AI 기반 자동 검증 시스템** 구축
- GPT-4o로 컬럼명 자동 매핑
- 3단계 규칙 기반 + AI 검증
- 진단 질문과 명부 데이터 교차 검증

## 9. 헤더 매칭 (3단계 하이브리드)

고객사마다 다른 컬럼명을 표준 스키마에 자동 매핑

### 3가지 매칭 도구

```
┌─────────────────────────────────────────────────────────────┐
│  1. Few-shot Learning (최우선)                              │
│     - 과거 성공 케이스에서 동일 헤더 찾아 즉시 매핑          │
│     - 가장 빠르고 정확 (사람이 검증한 결과)                  │
└─────────────────────────────────────────────────────────────┘
                           ↓ 매칭 안 된 헤더
┌─────────────────────────────────────────────────────────────┐
│  2. GPT-4o AI 매칭                                          │
│     - 의미 기반 매칭 (OpenAI API 사용)                      │
│     - 프롬프트에 Few-shot 예제 포함하여 정확도 향상          │
└─────────────────────────────────────────────────────────────┘
                           ↓ API 키 없거나 오류 시
┌─────────────────────────────────────────────────────────────┐
│  3. 규칙 기반 매칭 (Fallback)                               │
│     - 문자열 유사도 비교 (SequenceMatcher)                  │
│     - 유사도 65% 이상이면 매핑                              │
└─────────────────────────────────────────────────────────────┘
```

### Few-shot Learning이란?
> 소수의 예제만으로 학습하는 방식.
> 사용자가 수정한 매핑 결과를 저장해두고, 이후 동일한 헤더가 들어오면 저장된 결과를 바로 적용.

```
[학습 흐름]
1. 최초: "기준급여(원)" → AI가 "급여"로 매핑
2. 저장: 성공 케이스로 training_data/에 저장
3. 재사용: 다음에 "기준급여(원)" 들어오면 → Few-shot으로 즉시 매핑
```

### Graceful Degradation
```
OPENAI_API_KEY 있음  →  Few-shot → GPT-4o → 규칙 기반
OPENAI_API_KEY 없음  →  Few-shot → 규칙 기반 (AI 스킵)
API 오류 발생        →  규칙 기반으로 자동 전환
```
→ **API 키 없이도 시스템이 동작**함을 보장

## 10. 3단계 검증 시스템

### 10.1 Layer 1: 형식 검증 (하드코딩 규칙)

**코드로 고정된 검증 규칙들:**

| 분류 | 규칙 | 조건 |
|------|------|------|
| **필수 필드** | 8개 필드 존재 체크 | 사원번호, 생년월일, 성별, 입사일, 급여, 퇴직금추계액, 종업원구분 |
| **생년월일** | 연도 범위 | 1945년 ~ 2010년 |
| **급여** | 최저임금 체크 | 월 2,060,740원 미만 시 경고 |
| **급여** | 양수 체크 | 0 이하 시 오류 |
| **입사일** | 미래 날짜 | 현재보다 미래면 오류 |
| **입사일** | 18세 미만 입사 | 입사나이 < 18세면 오류 |
| **입사일** | 고령 입사 | 입사나이 > 70세면 경고 |
| **입사일** | 생년월일 선후 | 입사일 < 생년월일이면 오류 |
| **퇴직일** | 입사일 선후 | 퇴직일 < 입사일이면 오류 |
| **중간정산** | 기준일 선후 | 중간정산기준일 < 입사일-7일이면 오류 |
| **중간정산** | 금액-날짜 일치 | 금액 있는데 기준일 없으면 경고 |
| **성별** | 도메인 값 | 1, 2, 남, 여, M, F만 허용 |
| **종업원구분** | 도메인 값 | 1~4, 임원, 직원, 계약직만 허용 |
| **사원번호** | 중복 체크 | 동일 사원번호 2건 이상 시 경고 |
| **전화번호** | 형식 | 0으로 시작, 10~11자리 |
| **이메일** | 형식 | xxx@xxx.xxx 패턴 |

### 10.2 Layer 2: 교차 검증 (진단 질문 비교)

**진단 질문 답변 vs 명부 자동 계산 비교:**

| 비교 항목 | 진단 질문 | 명부 계산 | 허용 오차 |
|----------|----------|----------|----------|
| 재직자 수 | 2-a.1 + 2-a.2 + 2-a.3 | 행 수 (count) | 0명 (정확 일치) |
| 급여 총액 | 2-e (연간급여총액) | SUM(급여) | ±5% |

→ **인원수는 1명이라도 차이나면 경고**, 금액은 5% 허용

### 10.3 Layer 3: AI 검증 (GPT-4o)

**AI가 진단 질문 컨텍스트를 받아서 판단:**

```
[AI에게 전달되는 컨텍스트]
⚠️ 정년퇴직연령: 만 60세
   → 현재 나이가 60세를 초과한 직원은 오류로 판단
- 작성기준일: 2026-01-02
- 임원 인원: 8명
- 직원 인원: 110명
- 임금피크제 미적용
```

**AI가 수행하는 검증:**
- 정년퇴직연령 초과자 탐지 (진단 질문 `4-1` 기준)
- 이상치 분석 (최저임금 미달, 급여 범위 이상 등)
- 비즈니스 로직 판단 ("70세 입사자가 정상인가요?")

## 10-1. AI 학습 시스템 (Few-shot Learning)

### 학습 데이터 저장 위치
```
training_data/
├── cases/                    # 헤더 매칭 성공 케이스
│   └── index.json           # 케이스 인덱스
├── layer1_error_*.json      # L1 검증 오류 케이스 (50개+)
└── validation_*.json        # 전체 검증 결과 (50개+)
```

### AI가 학습하는 것들

#### 1. 헤더 매칭 패턴
```json
{
  "headers": ["사번", "기준급여(원)", "입사년월일"],
  "matches": [
    {"source": "사번", "target": "사원번호", "confidence": 0.95},
    {"source": "기준급여(원)", "target": "급여", "confidence": 0.92},
    {"source": "입사년월일", "target": "입사일", "confidence": 0.90}
  ],
  "human_corrections": {"중간정산일": "중간정산기준일"}
}
```
→ **사용자 수정 내역이 있으면 우선 적용** (human_corrections)

#### 2. 검증 오류 패턴
```json
{
  "category": "layer1_error",
  "input": {
    "error_type": "중간정산기준일",
    "error_message": "중간정산기준일이 입사일보다 앞섬"
  },
  "human_correction": {
    "should_detect": true,
    "rule": "중간정산기준일이 입사일보다 앞섬"
  },
  "is_correct": false  // AI가 틀림 → 다음엔 맞추도록 학습
}
```

### 학습 활용 방식

```
┌─────────────────────────────────────────────────────────────┐
│  새 파일 업로드                                              │
│  헤더: ["사번", "기준급여(원)", "입사년월일"]                 │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│  1. Few-shot 케이스 검색                                     │
│  → 유사 헤더 패턴의 과거 케이스 3개 찾기                     │
│  → 사람이 수정한 케이스 우선                                 │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│  2. GPT-4o 프롬프트에 예제 주입                              │
│  "과거 성공 매칭 예제:                                       │
│   예제 1: 사번 → 사원번호 (사람 수정: O)                     │
│   예제 2: 기준급여(원) → 급여"                               │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│  3. AI 매칭 + 저장                                           │
│  → 신뢰도 80% 이상이면 자동 저장                             │
│  → 다음 번에 Few-shot 예제로 활용                            │
└─────────────────────────────────────────────────────────────┘
```

### 현재 학습 현황
| 항목 | 개수 |
|------|------|
| 헤더 매칭 케이스 | 0개 (아직 축적 중) |
| L1 검증 오류 케이스 | 22개 |
| 전체 검증 케이스 | 28개 |

→ **사용할수록 정확도 향상** (Few-shot Learning 효과)

### 핵심 장점

#### 1. 깔끔한 UI
- **직관적인 단계별 흐름**: 로그인 → 진단 질문 → 업로드 → 결과 확인
- **시각적 피드백**: 오류/경고/정상을 색상으로 구분 (🔴/🟡/🟢)
- **반응형 디자인**: 다양한 화면 크기 지원

#### 2. 사용자(고객) 편의성
- **Basic/Complete 모드 선택**: 목적에 맞는 검증 수준 선택 가능
- **자동 헤더 매핑**: 고객사 엑셀 형식 그대로 업로드 가능
- **값 수정/값 유지**: 엑셀 없이 웹에서 오류 처리 가능
  - 값 수정: 잘못된 데이터 직접 수정
  - 값 유지: 정상 케이스 확인 후 목록에서 제거
- **원클릭 다운로드**: 검증 리포트 & 최종 명부 Excel 다운로드

#### 3. 보안 안정성
- **JWT 인증**: 토큰 기반 인증으로 세션 하이재킹 방지
- **RBAC 권한 관리**: 역할별 접근 제어 (5단계)
- **PII 자동 마스킹**: 민감정보 노출 방지
- **감사 로깅**: 모든 액션 추적 가능
- **AES-256 암호화**: 저장 데이터 보호
