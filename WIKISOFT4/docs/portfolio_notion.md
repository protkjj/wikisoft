## 프로젝트 소개

### 배경

퇴직급여채무 계리평가에서 사원명부 검증은 필수 업무입니다. 기존에는 담당자가 Excel 매크로로 수동 검증하며, 파일당 **3~4시간**이 소요되었습니다. 이메일로 파일을 주고받으며 개인정보(주민번호) 노출 위험도 존재했습니다.

### 해결

웹에서 파일을 업로드하면 **규칙 기반 + AI 하이브리드 검증**을 자동 수행합니다. 검증 결과를 인라인으로 수정할 수 있고, 사용자 피드백으로 시스템이 학습하여 반복 사용할수록 정확도가 향상됩니다.

### 핵심 기능

1. **진단 질문 위자드** — 7섹션 74개 질문으로 퇴직연금 제도 정보를 체계적으로 수집
2. **AI 헤더 매칭** — GPT-4o Few-shot 학습 기반으로 다양한 Excel 컬럼명을 표준 필드에 자동 매핑
3. **3-Layer 검증 엔진** — 형식 검증 → 교차 검증 → AI 검증을 파이프라인으로 실행
4. **인라인 수정 + 학습** — 웹 에디터에서 직접 수정하고, "값 유지" 피드백으로 false positive 자동 억제

       │        │        │
  ┌────▼──┐ ┌──▼────┐ ┌─▼───────┐
  │SQLite │ │OpenAI │ │Telegram │
  └───────┘ └───────┘ └─────────┘

### 3-Layer Validation Pipeline

| Layer | 이름 | 설명 | 속도 |
| --- | --- | --- | --- |
| L1 | Format Validation | 21개 규칙 기반 형식 검증 — 날짜, 숫자 범위, 필수값, 중복 탐지 | 0.1s |
| L2 | Cross Validation | 진단 질문 답변과 명부 데이터 교차 비교 — 인원수, 급여 총액 대조 | 0.5s |
| L3 | AI Validation | GPT-4o 기반 컨텍스트 추론 — 규칙으로 잡기 어려운 비즈니스 로직 검증 | 3~5s |

> 💡 **Graceful Degradation** — OpenAI API가 없어도 L1+L2 규칙 기반으로 100% 동작합니다. AI는 "필수"가 아닌 "향상" 수단으로 설계했습니다.

## 설계 결정

### 왜 하이브리드 (규칙 + AI)?

규칙만으로는 컨텍스트 판단이 불가능하고, AI만으로는 비용이 높고 결과 예측이 어렵습니다. 확정적 규칙으로 기본을 보장하고, AI로 복잡한 판단을 보완하는 방식을 선택했습니다.

### 왜 PII-free 설계?

보안은 사후 조치가 아닌 설계 원칙입니다. 개인정보가 필요 없는 검증 플로우를 설계하여 근본적으로 유출 위험을 제거했습니다.

### 왜 사용자 피드백 학습?

도메인 특성상 동일 패턴의 false positive가 반복됩니다. 사용자가 "값 유지"를 선택하면 해당 패턴을 학습하여 다음 검증에서 자동 억제합니다.
